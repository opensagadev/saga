# Hub bonus menu control flow (NDK r8e GCC 4.7)

`Hub_DrawBonusModeMenu` is a useful case where branch prediction and source order change large regions of the generated function. Measurements below use the GOT-aware `objdiff-cli` fork against `res/libTTapp.so`, with the Android NDK r8e x86 GCC 4.7 `-O3` configuration. The target function is 4,316 bytes.

The target begins with a branch to the arcade path, falls through into the ordinary bonus menu, and places an early shared return after the three validity checks on `hub_new_level`, its area index, and the area flag. The arcade path starts around offset `0x27b`, after the ordinary path has prepared its three labels, before its row rendering. A direct rewrite that put the ordinary path first did place the arcade branch near that offset, but GCC moved the shared return elsewhere. The object diff fell to 0%, despite several locally similar instructions. Block placement must be checked together with register allocation and return placement.

Keeping the arcade branch first in source while marking it unlikely with `__builtin_expect(bonusmodearcade, 0)` made GCC fall through into the ordinary path and restored the early shared return. In this version the arcade body landed around offset `0x80e`, later than the target, so the layout still needs work. Removing `__used__` from the now-called static helper first restored the target's internal register argument convention. Then the branch hint raised the helper's object match from 18.53% to 27.31%. Replacing the arcade row-zero check `i == 0` with `i != 1 && i != 2` raised it to 27.66%. The loop confines `i` to 0 through 2, so this check is equivalent within the loop. The target dispatches the arcade rows by comparing 1, then 2, then falling through to 0.

The remaining large difference is stack allocation: the target reserves `0x220` bytes and places the text buffers at `esp+0xa0`, `+0x120`, and `+0x1a0`; the branch-hinted candidate reserves `0x240` bytes and places them 32 bytes higher. The hint changes when GCC spills `alpha`, so avoid judging a branch rewrite by source order alone. Inspect the prologue, early exit block, and key stack slots before refining the individual draw calls.
