# Episode VI target reconstruction notes

The `res/libTTapp.so` target is the Android x86 NDK r8e build. Measure
function matches with the GOT-aware fork of `objdiff-cli`; a raw byte diff
overstates differences from changed GOT and constant-pool positions.

Final measured matches for this batch: `SarlaccPitA_Draw` 99.885% (252
bytes), `DeathStar2BattleFire_Init` 99.792% (220 bytes),
`SarlaccPitB_Init` 99.904% (1,091 bytes), and `SarlaccPitB_Reset`
87.159% (1,037 generated bytes against 1,045 target bytes). The first
three have the target instruction count and differ only in literal or
static-data address operands. The reset handler still needs register and
loop-order tuning.

## Sarlacc Pit A boss panel

`SarlaccPitA_Draw` first tests `gizaimessagesys`, then looks up `Boba_Dead`.
When the message is missing or its value differs from `0.0f`, it draws an
empty boss bar by calling `DrawBossHitPoints(NULL)`. Otherwise it finds Boba
Fett with `FindGameObject(id_BOBAFETT, 1, 1, 1, 0)`, looks up
`BobaFightStarted`, and draws Boba's bar only when that second message is
`1.0f`. The target keeps the first message pointer in a register until the
second lookup; preserving one local `message` variable helps match that
register lifetime.

The target checks equality with `ucomiss`, then a parity branch followed by
`jne`. GCC thereby rejects unordered comparisons as well as unequal values.
Using an ordinary floating equality in C++ produces this sequence; avoid
replacing it with an integer or bitwise comparison.

## Death Star fire initializer

`DeathStar2BattleFire_Init` installs `DeathStar2BattleFire_SetSlowDownMul`
in `LEGO_SET_SLOWDOWNFN`, stores the `"fire"` spline in `LevelCodeSpline[0]`,
finds the `"fire_cube"` special, initializes two `SPLINEPOS_s` records from
the spline, clears `runningTotalPos`, and sets `fireSpeedScale` to `1.0f`.
The special lookup uses the global `WORLD` scene, while the spline lookup
uses the function's `world` argument. Both spline-position calls pass zero
distance and zero looping.

## Sarlacc Pit B initializer layout

The original `SarlaccPitB_Init` clears a 1024-byte local static object named
`sarlaccdisco`, allocates a 20-byte level packet, and loops over up to 16
numbered disco effects. Five arrays of 16 `nuhspecial_s` records begin at
offsets `0x4`, `0xc4`, `0x184`, `0x244`, and `0x304` in `sarlaccdisco`.
Each record is 12 bytes. A signed byte at offset `0x3dc` is the active
effect count. The target formats each name with a leading zero for values
1 through 9 and without it for 10 through 16; forcing a single `%02d`
format can change the generated block order and literal references.

Caching the signed effect index and its `index + 1` display number in locals
made GCC carry them across the five `sprintf` and `NuSpecialFind` pairs. The
result was 1,151 bytes and only 41.669% match. Reading the signed byte from
the state block for each name, destination, and existence check restored the
target's register lifetimes and branch order: 1,096 bytes and 99.482% before
the final five-byte cleanup. Likewise, load the first special's Y coordinate
once into a local before writing it to the two height fields; two direct
`position->y` expressions make GCC reload it after the first store because
the compiler cannot exclude aliasing.

`SarlaccPitB_Reset` uses the same state block. It clears counters at offsets
`0x3cc` through `0x3e0`, iterates over the signed count to set the off
special visible and the flash/on/finish specials hidden, then stores three
message pointers at `0x3f0` through `0x3f8`. These offsets fall *inside*
the 1024-byte `sarlaccdisco` object despite looking like independent globals
in a decompiler. Its seven `LevSpecial` lookups and four object lookups use
the passed `world`, while the initializer's loop uses the global `WORLD`.
The target reloads the signed effect count and recomputes `12 * index` on
each reset iteration. Simply removing a cached count from this source made
GCC choose a different register and block schedule and reduced the measured
match from 87.159% to 75.221%; it was reverted. Further tuning needs a
loop-shape change, not just an extra count read.
